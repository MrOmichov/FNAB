# Сохранения FNAB

Документ описывает реализованный контракт сохранений между ночами и источники будущих данных. **VERIFIED** — подтверждено автором, исходниками или указанной проверкой; **LIKELY** — трактовка материала; **UNKNOWN** — правило не определено.

## Требования автора

**VERIFIED:** «Новая игра» сбрасывает текущую кампанию, сохраняя достижения и открытия. Победа открывает следующую ночь, «Продолжить» начинает её с начала; поражение оставляет текущую ночь. Энергия, время, расположение AI, дверь, вентиляторы, камеры и откат шокера в файл не записываются.

## Владение и интеграция

`SaveGame` — один Autoload общеприложенческого прогресса. `Global.night_number` остаётся отражением активного профиля для существующих изображений, а не сохранённой контрольной точкой. Night владеет состоянием текущей смены; UI запрашивает действия и показывает ошибки.

Меню сохраняет новую кампанию до запуска N1. Continue готовит существующий профиль контрольной точки. Night потребляет одноразовый запрос до сброса AI и пишет checkpoint только для запусков кампании из меню. Прямой запуск Night из редактора и тестовые профили не меняют пользовательский прогресс. Повтор результата запускает сыгранную ночь, Continue — следующую сохранённую.

Есть профили N1–N6. После победы N6 контрольная точка остаётся N6. Это ограничение имеющихся профилей, а не реализация своей N7 или финальной сюжетной цепочки. Победы не выдаются за завершённые концовки: звёзды и достижения автоматически за N5/N6 не начисляются.

## Файл и API

**VERIFIED по исходникам:** `scripts/save_game.gd` зарегистрирован в `project.godot` как `SaveGame`. Файл `user://progress.json`, формат JSON `schema_version = 1`; предыдущая исправная запись хранится в `progress.json.bak`. Запись проходит через проверяемый `.tmp` и замену с восстановлением прежнего файла при ошибке переименования. Это не гарантия сохранности при любом аппаратном сбое. В Windows обычный путь — `%APPDATA%/Godot/app_userdata/FNAB/progress.json`; Android использует собственный каталог приложения.

| Раздел | Поля и назначение |
|---|---|
| `campaign` | `started`, `next_night`, `highest_completed`, `id`, `flags`, `completed_minigames`; новая игра сбрасывает этот раздел, повышая ID кампании |
| `unlocks` | `nights`, `stars`, `achievement_ids`, `ending_ids`, `secrets` по номеру ночи, `completed_minigames`; сохраняется при новой игре |
| `custom_levels` | `berry`, `blacky`, `dog`, `sann`, `old_creeper`, целые 0–20 |
| `settings` | `language` (`ru`/`en`), `fullscreen` (bool); пока только хранение, без применения к игре |

Методы: `start_new_campaign()`, `can_continue()`, `get_checkpoint_night()`, `prepare_night()`, `consume_night_request()`, `record_night_win()`. ID кампании отклоняет запоздалую победу от предыдущей новой игры; повтор старой ночи не уменьшает checkpoint. `get_snapshot()` возвращает копию данных. Сигналы `save_changed`, `save_error` сообщает SaveGame; Night передаёт ошибку победной записи через `progress_save_failed`.

Будущие системы вызывают `unlock_achievement()`, `unlock_ending()`, `unlock_star()`, `discover_secret()`, `complete_minigame()`, `set_campaign_flag()`, `set_custom_levels()`, `set_settings()`. Концовки: `bad_ending`, `neutral_ending`, `middle_ending`, `canonical_ending`; мини-игры: `computer`, `dog`, `assemble`, `walk`. Звёзды — 1–3. Идентификаторы достижений, секретов и флагов — стабильные строки из строчных латинских букв, цифр и `_`, начинающиеся с буквы.

При повреждении основного файла загрузчик использует исправную резервную копию. Если оба файла повреждены либо распознан более новый формат, автоматическая перезапись блокируется; ошибка видна в меню. Ошибка записи не меняет данные в памяти и не отменяет победу, но следующий checkpoint не записывается; результат показывает предупреждение. Отсутствие файла означает новый профиль и отключённую кнопку «Продолжить».
## Будущие системы

Файл допускает хранение открытий, мини-игр, секретов, уровней своей ночи и настроек через явные методы SaveGame. Наличие сохранённых полей не означает реализацию их экранов, условий получения наград, мини-игр или настройки языка. Эти различия должны сохраняться при следующих изменениях.

## Защита будущего формата

**VERIFIED по исходникам и повторному review:** `SaveGame._read_document()` проверяет конечный целочисленный `schema_version` сразу после разбора корневого JSON-объекта, до нормализации остальных значений. Версия выше поддерживаемой блокирует запись даже при неизвестных дробных полях и исправной резервной копии старого формата. Тест проверяет отказ New Game, записи победы, звезды и настроек, а также неизменность основного файла и backup. Проверка версии не зависит от будущей структуры данных.
